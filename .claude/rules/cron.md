## Cron Jobs (Automated Intelligence Pipeline)

| Cron Job | Schedule | Purpose |
|----------|----------|---------|
| `seo-guardian` | Weekly Sunday 10 AM UTC | v11.11.0 — SEO Guardian Phase 1 (report-only). Pulls 28-day Google Search Console query+page data (zero-dep service-account client, `src/lib/seo/gsc-client.ts`), deterministic aggregation prepares FACTS (striking-distance list is "a convenience, not a boundary" — the AI may bet on anything in the data), then an **Opus 4.8** strategist writes the weekly report + 2-5 dated BETS (falsifiable expected outcomes, graded later against real GSC data — Learning Loop). Stored in `ss_seo_reports`, emailed to `GUARDIAN_ALERT_EMAIL`. Runs `not_configured` (soft) until the GSC service account exists — see `SEO-GUARDIAN-SETUP.md`. Content bets execute via LGAAS (`LGAAS-WORK-ORDER-SEO-GUARDIAN.md`). Since v11.41.5 the strategist also gets each top/bet-target page's live title, meta, headings and anchor ids (`src/lib/seo/page-state.ts`), so it can tell work that never shipped from reworded work; handing bets to LGAAS is still manual. Phase 3 grader not yet built. |
| `grade-nudge-outcomes` | Weekly Sunday 8 AM UTC | v10.11.0 — The MEASURED teacher for the nudge learning loop. For each acted-but-ungraded nudge, checks whether the user's Glass Skin Score moved in the ≥14 days after she acted — gated hard on attribution + confounders (acted-only, phase-consistent, photo-quality-confidence ≥0.85, ±4-point noise band) and ABSTAINS (`insufficient_data`) rather than fabricate a verdict when data is sparse. Pure deterministic measurement, no AI. Writes `outcome_grade`/delta/score-ids/notes onto `ss_user_nudges`. The graded helped-rate per nudge_type feeds back into `pickNudgeOpportunity` (suppresses clearly-underperforming types). Backs `src/lib/intelligence/nudge-outcome-grader.ts`. See `NUDGE-OUTCOME-TEACHER-BLUEPRINT.md`. |
| `proactive-nudge` | Daily 3 PM UTC | v10.10.0 — Proactive nudge engine. Per active subscriber, computes the single best well-timed nudge opportunity (open loop ≥5d stale, treatment-phase/routine mismatch, cycle-timed actives loop in a follicular/ovulatory window, or glass-skin cadence ≥14d) via `src/lib/intelligence/nudge-eligibility.ts` (pure, no AI). Timezone-gated (only queues 9am–8pm local), capped (MAX_NUDGES=3, SPACING_DAYS=3), no-guilt escalation ladder. Generates the Yuri-voiced message with **Opus 4.8** (user-facing — Principle 1; deliberately NOT Sonnet) and writes to `ss_user_nudges` (status pending). Dashboard surfaces it via `/api/me/nudge` + `YuriNudgeCard`. Routes to Yuri via prefilled `?ask=` (Yuri Sole Authority Principle — nudge invites, doesn't recommend). See `PROACTIVE-NUDGE-BLUEPRINT.md`. |
| `yuri-wakes-up` | Hourly :30 (grading + leads once a day at 16:00 UTC) | UNRELEASED (Oct 9-10 2026). Hourly so every timezone's 9am-8pm local window is reachable; each subscriber is judged at most once per local day (unique index). Yuri decides whether to reach out FIRST: speak-or-silent subscriber check-ins from her full chat memory (`MODELS.chat`; no tools; the prompt forbids prescribing a product/actives change and the content guard blocks any routine change), and at most one email per WIDGET lead ever (registered cohort, any former/current payer, comped/admin/demo excluded; only after the Honest Three finished AND `LEAD_REENGAGE_AFTER_LAST_EMAIL_APPROVED`; blocked without `EMAIL_POSTAL_ADDRESS` or `RESEND_API_KEY`). Every draft passes `content-guard.ts` (two reads by MODELS.primary + deterministic quote/stance checks; it can only enforce what the readers list). Every decision incl. silence and crashes → `ss_proactive_judgments`; leads graded by chat restart/conversion/unsubscribe/bounce, subscribers by ATTRIBUTABLE response only (acted / sent the ask / replied on topic, with their baseline chat rate recorded); graded record fed back into the next judgment (dogfood rows excluded). Shares the nudge cap (`nudge-limits.ts`). Live only with `YURI_WAKES_UP_MODE=live`, else logs mode `off`. Dry run: `scripts/dry-run-yuri-wakes-up.ts`. Scoreboard + per-`utm_source`×`utm_content` funnel (from `ss_campaign_touches`) on `/admin/widget`. |
| `settle-memory` | Hourly :10 | UNRELEASED (Oct 10 2026). Runs summary, THEN decision memory, THEN treatment phases (the advisor's own functions, never concurrently: two writers of `decision_memory`) on conversations idle 30+ min and not settled since their last message (`memory_settled_at`, set only when every step succeeded), including onboarding. Failures back off 1→32h and stop after 6 attempts (counted in the run row); external users first. Default scope: each user's 3 most recent conversations or active in 60 days. Closes the cadence gap (advisor extracts only at msg 2, 6, every 5th). Open loops close only via an evidence-quoted resolution and are SOFT-closed (`resolved_at`, reversible; reopening needs evidence too); readers filter with `isOpenLoop`. Run row every invocation. Backfill: `scripts/backfill-memory-settle.ts` (dry-run default, `--all` widens). Needs migrations `20261010000001` + `20261010000002`; the cron and `--apply` REFUSE without them. **`ss_yuri_conversations.updated_at` = last ACTIVITY**: since `20261010000002` its trigger keeps `updated_at` when only memory bookkeeping columns change (summary, decision_memory, settle state, truncation/learning flags). If you add a bookkeeping column, add it to that trigger's list or every background write will reorder users' conversation lists (readers order by `updated_at`). Check: `scripts/sql/check-conversation-updated-at.sql`. |

**Pipeline daily chain**: `scan-korean-products` (6 AM, Mondays only) scrapes new Olive Young listings → `scan-korean-bestsellers` (6:30 AM) captures Korean sales rankings → `translate-and-index` (7 AM) runs Sonnet extraction on pending products → `link-ingredients` (7:30 AM) links ingredients → `scan-trends` (8 AM) detects trending products from activity spikes → `scan-reddit-mentions` (8:30 AM) scans English K-beauty communities → `calculate-gap-scores` (9 AM) cross-references Korean rankings vs US mentions.

**Where-to-buy (Oct 21 2026, v11.43.0)**: `ss_retailers.ships_to_us` is a fact on every price row (Olive Young Global = false; it stopped shipping to the US May 29 2026; "Olive Young US" row added). Only a price at a recommended store that ships to the US is shown as "the price" or published to Google (`src/lib/pricing/price-scope.ts`, shared by product/best-of pages, `/api/prices` and the LGAAS search endpoint). Policy is ROUGH US prices, not exact tracking. Yuri gets a visitor-country fact in the widget. Next step not built: match the catalog to Olive Young US (its `/api/proxy/storefront/api/v1/q/products/{UA id}` feed is server-readable; search needs Playwright).

**Price freshness** (partly superseded above): Two dedicated price crons run daily with the full Vercel Pro 300s budget — `refresh-prices` (6 AM UTC, Soko Glam via Shopify JSON API, ~150 products/run) and `refresh-prices-yesstyle` (6 PM UTC, YesStyle via Playwright, ~80 products/run). Combined: ~230 products/day, full catalog cycle in ~25 days. Both snapshot all prices to `ss_price_history` and flag >10% price drops as trend signals. Amazon and StyleKorean remain CLI-only (CAPTCHA/AJAX issues).
